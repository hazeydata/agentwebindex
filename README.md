# AgentWebIndex v1 (site + collectors)

Static site (plain HTML/JS + a 40-line Python generator) and two Python collectors (stdlib only, no deps).
Spec: `../PLAN.md`. Nothing here contains hard-coded prices or benchmark numbers; every page shows
"No data yet" until real files exist under `data/`.

## Layout
- `src/` page sources (`_layout.html` wraps each page), `app.js` renders data client-side
- `build.py` → `dist/` (pages + copy of `data/` + `llms.txt`)
- `collectors/providers.json` provider list, pricing URLs, key env-var names
- `collectors/snapshot_prices.py` daily pricing-page snapshot + diff → `data/prices/<id>.json`, `data/prices/history/<id>.jsonl`, `data/prices/index.json`. It skips any provider whose `tos_matrix.yaml` entry fails `gates.vendor_confirmed` (`snapshot_providers()`, AC24g): an unconfirmed vendor's pricing page (Context.dev today) is never fetched and gets no published `data/prices` file.
- `collectors/benchmark.py` harness → `data/benchmarks/latest.json` (+ `smoke-latest.json` / `full-latest.json`)
- `.github/workflows/prices.yml`, `.github/workflows/benchmark.yml`

## Run locally
```
python3 build.py
python3 -m http.server 8765 -d dist     # http://localhost:8765/
python3 collectors/snapshot_prices.py   # fetches each pricing page once (network)
python3 collectors/benchmark.py --mode smoke   # skips any provider whose key env var is unset
python3 build.py                        # rebuild to pick up new data
```

## Benchmark (SPEC-bench v1), see bench/README.md
Spec: [SPEC-bench.md](SPEC-bench.md).
- Sets live in `bench/sets/`: `search_evergreen.jsonl` (100 rows), `scrape_urls.jsonl` (150 rows), `browser_tasks.yaml` (20 tasks) and the weekly `news_YYYY-WW.jsonl` sets, frozen against the manifest named in `bench/config.yaml` and checked by `python -m awibench.validate`. `bench/pricing.yaml` and `bench/tos_matrix.yaml` carry verified values where captured; a value not on the vendor's page stays `NOT CAPTURED` (pricing) or null (ToS) and shows as "n/a".
- Live runs: free tier only, `MONTHLY_CAP_USD` must be `0` (D4). The runner stops a provider before a call would exceed its free quota and marks the run `stale_quota`. Quota usage goes to `data/spend/YYYY-MM-quota.json` and logs to `bench/runs/YYYY-MM-DD/<provider>/<set>.jsonl`. Tables are built from those logs into `data/benchmarks/latest.json`.
- Cron (UTC): news set Mondays 10:00 (06:00 ET during EDT; change it to 11:00 for EST); full run Mondays 11:23; re-probes Mon 17:23 (+6 h), Tue 11:23 (+24 h) and Thu 11:23 (+72 h); smoke run daily 10:41.
- Context.dev (AWI-PROVIDER-CONTEXTDEV-001 spec rev 4, search + scrape, free tier only; plain-text name, no logo): key env `CONTEXT_DEV_API_KEY` (no key = `skipped_no_key`). **Live-run gate (R9):** config `free_tier_guard.contextdev.live_run_allowed` is `false` and `vendor_confirmation` is `null`, so every run records `skipped_no_vendor_confirmation` and makes zero calls (the Monday news job included) until written vendor confirmation is recorded and both are set in a separate PR. **Anchor-window guard:** the 1,000 free credits refill on the org's grant-anchor day (`grant_anchor_day`, unknown = `null`, so the counter never resets); before every attempt `max(usage meter, attempts counter) + the call's credits` must be `<= 900` (`stop_at_credits`), every attempt counts billed or not, and a corrupt, unreadable or locked counter or an unreadable meter stops it as `stale_budget` (fail closed). Calls are serial with `max_concurrent` 1 (cap 1). Credit rule (F4): scrape 1 (2 with browser actions); search 1 per 10 results (rounded up), +1 per 10 each for markdown and highlights. Billing rule (F5): 2xx and 404 bill the credits; validation, 401, 403, 408, 429, 5xx and no response bill 0; a 429 with `Retry-After` is retried once after the wait; 402 or 401 `USAGE_EXCEEDED` is a quota stop (`stale_quota`, no retry). **Publishing:** `publish_hold: ["contextdev"]` keeps it out of `latest.json`, `data/` and `dist/` in this build; the publish gate additionally needs a numeric entry price (P0, not captured: sources conflict) and a terms verdict `allowed` (P1, `unverified`); `providers.json` carries the optional `exclude_from_also_priced: true` (absent = false) so it stays out of the "Also priced" line. Details in bench/README.md.
- Tests: `./run_tests.sh` (pytest `tests/test_bench.py`, the mock dry run, the secrets scan); or `cd bench && python -m pytest tests/test_bench.py` (mock only, pytest `tmp_path`) and `python tests/dry_run.py`, which runs the full mock pipeline in a temp dir that it removes.

- Vendor-confirmation publish gate (R10, AC24a-24h): a `tos_matrix.yaml` entry with `vendor_confirmation_required: true` publishes nothing (no table row, freshness, `not_run_yet`, skip, run-summary entry, and no `exclusions` entry in `latest.json`, no data/CSV/dist, no Prices row) and is never called (`skipped_no_vendor_confirmation`) until its `vendor_confirmation` is a record that passes `gates.record_error`, the ONE record validator (spec R19, shape at spec line 95; `vendor_confirmed()` and the CI schema check both call it): a mapping with exactly the keys `date`, `sender`, `quote`, `evidence_path` and `recorded_pr` (no extra keys); `date` a quoted `YYYY-MM-DD` string that is a real calendar date (an unquoted YAML date fails); `sender` a non-empty string; `recorded_pr` a non-empty `https://` URL; `quote` and `evidence_path` each a string or null, with at least one non-empty. There is ONE implementation, `gates.vendor_confirmed(tos_entry)` in `bench/awibench/gates.py`; `tables.build`/`held_providers`, the runner, `collectors/benchmark.py` and `guard.live_allowed(cfg, tos)` all use it, and `gates.publishable(pid, pricing, tos)` adds the other gates (AC23 for contextdev). Providers without the flag are unaffected. Required today: `contextdev` and `keenable`, both with `vendor_confirmation: null`. Keenable is gate-only: a `tos_matrix.yaml` entry (its terms bar sharing benchmark results) and nothing else, with no `providers.json`, `pricing.yaml` or config entry, no adapter and no live call. Recording a reply (`vendor_confirmation`, and `live_run_allowed` for contextdev) must go in its own FLIP-ONLY PR (R13): `python -m awibench.confirmation_diff [BASE]` (run from `bench/`, default `origin/main`) is structural: it parses `bench/tos_matrix.yaml` and `bench/config.yaml` at the merge-base and at HEAD, compares them field by field, and fails when a confirmation field changes together with anything outside the flip allowlist. The allowlist is: fields inside `providers.<pid>.vendor_confirmation` of ONE flipped provider (any record field: date, sender, quote, evidence_path, recorded_pr); `free_tier_guard.<pid>.live_run_allowed` and `.vendor_confirmation` for that same provider; the vendor-reply evidence file (`[agentwebindex-meta/]cycles/<cycle>/evidence/<file>`, one path segment) and the cycle docs `cycles/<cycle>/summary.md` and `cycles/<cycle>/decisions.md` (only those two names, only directly under `cycles/<cycle>/`; e.g. `cycles/README.md` is rejected). Any other changed key (e.g. `providers.contextdev.benchmarking.quote`, another provider's fields, other config fields), and code, tests, `pricing.yaml`, `providers.json`, README or any other file, are rejected. A price from the vendor reply lands in a separate PR. It runs on every pull request (`.github/workflows/confirmation-diff.yml`, base `origin/<base branch>`, advisory) and in `run_tests.sh` (base `AWI_CONFIRMATION_BASE`, default `origin/main`; a missing base fails, and a confirmation_diff failure makes the script exit 1). Bootstrap allowance: a confirmation field that is new at HEAD (absent at the base) and holds the closed default (`null` or `false`) does not count while no entry in `tos_matrix.yaml` or `config.yaml` holds any non-null `vendor_confirmation` or `live_run_allowed: true`, so the PR that introduces a gated provider can carry code; removed fields, changed values, or a HEAD with anything confirmed still fail. AC24h (any PR, not only flips): `confirmation_diff` also fails when an entry that has `vendor_confirmation_required` at the base is lowered, meaning the value goes from `true` to anything else, or the key or the whole entry is deleted or renamed. Deleting or renaming the key fails whatever its base value (`true`, `false` or `null`), per R15. Adding a new gated entry or editing unrelated fields passes. There is no override: lowering the gate needs a separate Fred or CEO ruling. Base-judged CI (R15): `.github/workflows/confirmation-diff-base.yml` runs on `pull_request_target`. It checks out only the base, fetches the PR head as git data, copies the BASE `confirmation_diff.py` and `gates.py` into a temp dir (the flag name comes from the base `gates.py`), and runs them against the PR diff (`python -m awibench.confirmation_diff BASE HEAD` with `AWI_REPO_ROOT`). This base-judged job is the authoritative check: in it, a PR's own checker, gates.py or workflow never judges that PR, and no PR code is executed. The `pull_request` job in `confirmation-diff.yml`, and the run in `run_tests.sh`, run the PR's own checker; they are advisory self-tests, not the gate. R16: (SQ1, R17 SQ-A) If the base has no `confirmation_diff.py`, the job FAILS (fail closed) with no exemption, not even for a PR that adds the checker: an added checker is content the PR controls (an empty file or `sys.exit(0)` would pass). #27 itself is not judged by this job (`pull_request_target` runs main's workflows, and main has none before #27 merges); its control is Kitty's fixtures, the mutants and Weatherman's SHIP at its exact head. (SQ2) The checker also fails any diff that touches a file in `confirmation_diff.PROTECTED` that exists at the base: `bench/awibench/gates.py`, `bench/awibench/confirmation_diff.py`, `.github/workflows/confirmation-diff.yml` and `.github/workflows/confirmation-diff-base.yml`. A file absent at the base is not judged by SQ2 (with no base checker, SQ1 already fails closed). Once #27 merges, any later change to these files needs a separate Fred or CEO ruling. (SQ3) Values compare strictly on type and value: `false` to `0`, `'false'` or `null`, and `true` to `1` or `'true'`, are all changes and fail (the bootstrap allowance accepts only a literal `null` or `false`). (R17 SQ-C) On every PR, flip or not, the head is type-checked: `vendor_confirmation_required` and `live_run_allowed` must be bool, and `vendor_confirmation` must be null or pass `gates.record_error` (R18/R19). A data-only `false` to `0`, a bare link or other string, a falsy value (`""`, `0`, `false`, `{}`, `[]`), a set, an extra or missing key, an unquoted or impossible date, a non-`https://` or integer `recorded_pr`, or a record whose `quote` and `evidence_path` are both null or empty, fails. Base used: the base-judged job diffs from merge-base(base sha, PR head); the advisory `confirmation-diff.yml` uses `origin/<base branch>` and `run_tests.sh` uses `AWI_CONFIRMATION_BASE` (default `origin/main`), both also from the merge-base. After #27 merges, the chief re-runs every open PR against the new base and records the list in the cycle summary.md (R17 SQ-B). Still open: a branch ruleset must make this check required (Fred). Changed paths are read NUL-separated and without rename detection (`git diff --name-only --no-renames -z`), and path rules use full matches. A space or a trailing newline therefore cannot smuggle a path through, and a `git mv` of code, tests, `run_tests.sh` or a workflow into `evidence/` still lists the old path and fails.
