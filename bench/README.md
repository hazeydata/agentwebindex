## Context.dev (search + scrape, free-tier credit guard)
AWI-PROVIDER-CONTEXTDEV-001 spec rev 4 (Side Hustle CEO R1-R9, fact desk F1-F7, 2026-10-25). Display name is the plain text "Context.dev"; the logo is never used. Key env `CONTEXT_DEV_API_KEY`; with no key the provider is `skipped_no_key`. `keyed_providers()` lists it only when that variable is non-empty. Free tier only: `free_tier_guard.contextdev.paid_tier` is `false` (the runner raises `CapViolation` otherwise), no code path reads a paid key, and `CapViolation` also fires if billed credits pass `quota_credits` (1,000).
- **Live-run gate (R9, AC6a/AC25):** `guard.live_allowed(cfg, tos)` is true only when `live_run_allowed` is `true` AND config `vendor_confirmation` is set AND the tos_matrix record passes `gates.vendor_confirmed` (R10). The committed config has `false`/`null`, so contextdev is `skipped_no_vendor_confirmation` (zero adapter calls even with a key, no run-log lines, no counter change, no meter call) in every run, the Monday news job included, and the run continues for the other providers. It is listed in `month1_free_tier_providers` but the gate blocks it. Both fields change only in a separate PR after the vendor reply is recorded.
- **Adapters** (`collectors/benchmark.py`): `_contextdev_search` (POST `https://api.context.dev/v1/web/search`) and `_contextdev_scrape` (POST `https://api.context.dev/v1/web/scrape`), `Authorization: Bearer` header only. Endpoint paths and field names come from docs.context.dev and are **unverified** (never called live). The key never goes in a URL; adapters and the runner replace it with `***` in every error text. A 429 error text carries the `Retry-After` header value.
- **Credit rule (F4, `guard.contextdev_credits(kind, request, n_results)`):** scrape = 1 (2 with browser actions); search = `ceil(results/10)`, plus `ceil(results/10)` if markdown, plus `ceil(results/10)` if highlights. The pre-call estimate uses the requested result count (`guard.contextdev_request`, 10 results, so 1 credit); billing uses the returned count. Recorded in pricing.yaml as `credits_per_call` and `credits_per_call_rule` (docs.context.dev/account/credits).
- **Anchor-window guard (F1, `guard.CreditGuard`, `guard.anchor_window_start`):** the free tier refills on the org's grant-anchor day, not the 1st. `grant_anchor_day` is `null` until Fred reads it from the dashboard; `null` means the counter never resets (one file `contextdev-unanchored.json`, fail closed) and the run summary carries `guard_note: "grant anchor not configured; ..."`. With a day set, the counter file is `contextdev-<window-start YYYY-MM-DD>.json` (config `counter_file`, directory `data/spend/`, written atomically under an `fcntl` lock): window start = the most recent anchor day on or before the call's UTC date, clamped to the month length (anchor 31 -> Nov 30). A run on the 14th continues the old window, the 15th starts a new file at 0, the 1st does not reset.
- **Guard check (AC11, `guard.CreditGuard.allows(next_credits, meter)`, the single check the runner calls):** before every attempt, `max(meter credits_used, attempts counter) + the call's credits` must be `<= stop_at_credits` (exactly 900, R2). Otherwise the provider stops as `stale_quota` before the adapter is called, the run-log lines so far are written, the summary carries `credits_used`/`credits_stop_at`, and other providers still run. 899 + scrape (1) runs; 899 + a 10-result search with markdown (2), or 900 + anything, stops. **Every attempt counts** at its credit cost, billed or not (R1); the guard reads the attempts counter, never the billed one.
- **Fail closed (AC14):** a corrupt, wrong-window, unreadable or locked (past `lock_timeout_s`) counter, a missing file when a later window file exists, or a counter write that fails, stops the provider as `stale_budget` with reason "credit counter unreadable; failing closed". No adapter call is made.
- **Meter (AC26):** `contextdev_meter(key)` is a read-only `GET https://api.context.dev/v1/org/usage` (0 credits; docs https://docs.context.dev/api-reference/usage/retrieve), returns `period.credits_used` or `None`; the meter client never issues POST/PUT/PATCH/DELETE. `main()` wires it as `meters={"contextdev": ...}`; a supplied meter that is unreadable (error, `period: null`, bad value) stops the provider as `stale_budget`. Each run logs meter, counter and the gap to `contextdev-meter-YYYY-MM.json` and the run summary.
- **Concurrency (AC10):** calls stay serial and each adapter call acquires a `max_concurrent` semaphore; `max_concurrent` is **1** (cap 1: the pricing page says 2, the billing doc says 1, F2).
- **Billing rule (F5, `guard.contextdev_billed(http_status, body, credits)`, cost math only):** 2xx and 404 bill the credits (a 404 is scored as a fail); 400/422 validation bill 0; 401 (not USAGE_EXCEEDED) and 403 bill 0 and stop as `auth_error`; 408, 5xx bill 0; 429 bills 0 and is `rate_limited` (outside the pass-rate denominator; more than 20% 429 makes the run stale); no response bills 0 (`unbilled_no_response`). A 429 with `Retry-After` waits that many seconds (config `retry_after_429_s`, 1, is the fallback) and retries once; each attempt is its own guard entry and log line. HTTP 402 or 401 with `USAGE_EXCEEDED` (`quota_stop_errors`) is an immediate quota stop: no retry, billed 0, the line is logged with status `quota_stop`, the provider is `stale_quota` (not `auth_error`) and the others run.
- **Publishing (AC5, AC23, AC24):** config `publish_hold: ["contextdev"]` keeps every contextdev row, freshness entry, `not_run_yet`, skip and run-summary entry out of `latest.json` (run logs under `bench/runs/` are still written). `tables.publish_gate` (config `publish_gate`) requires BOTH P0 (a numeric entry price with `source_url` and `checked_at` in pricing.yaml) AND P1 (tos_matrix `full_read` true, `verdict` `allowed`, `allowed` `yes`, benchmarking and publishing_results not forbidden). Today it is closed: P0 is not captured and P1 is `unverified`; the hold applies even when both pass. A `forbidden` `benchmarking` or `publishing_results` status puts any provider under `exclusions` and stops it from running.
- **pricing.yaml / tos_matrix.yaml:** `contextdev` has no price (F3): every `tiers` field is `NOT CAPTURED`, `note` quotes the conflict ($20/10k card, $19 FAQ, 7,500 docs; overage $3.00 vs $2.20 per 1k), so `cost_columns()` returns n/a. `free_tier` is 1,000 credits/month, `needs_card` false, refill "grant-anchor day". tos_matrix: terms at `/term`, 27 sections, `verdict` `unverified`, `allowed` null, verbatim quotes (automated access `forbidden_literal` from sections 4 and 8; attribution `marks_restricted`).
- **providers.json:** optional boolean `exclude_from_also_priced` (absent = false; new field, snake_case like the rest) keeps a provider out of the site's "Also priced, no published results yet" line; `tables.also_priced_providers(pricing, latest, providers)` mirrors the site's rule (providers in pricing.yaml with no published row) minus flagged providers: 11 names today. The site repo's `untested_providers()` must read the same flag.

## Vendor-confirmation gate (R10)
Vendor-confirmation publish gate (R10, AC24a-24h): a `tos_matrix.yaml` entry with `vendor_confirmation_required: true` publishes nothing (no table row, freshness, `not_run_yet`, skip, run-summary entry, and no `exclusions` entry in `latest.json`, no data/CSV/dist, no Prices row) and is never called (`skipped_no_vendor_confirmation`) until its `vendor_confirmation` record holds a `date`, a `sender` and a `quote` or `evidence_path`. There is ONE implementation, `gates.vendor_confirmed(tos_entry)` in `bench/awibench/gates.py`; `tables.build`/`held_providers`, the runner, `collectors/benchmark.py` and `guard.live_allowed(cfg, tos)` all use it, and `gates.publishable(pid, pricing, tos)` adds the other gates (AC23 for contextdev). Providers without the flag are unaffected. The daily price snapshot (`collectors/snapshot_prices.py`, `snapshot_providers()`, AC24g) skips the same providers, so an unconfirmed vendor's pricing page is never fetched or published under `data/prices`. Required today: `contextdev` and `keenable`, both with `vendor_confirmation: null`. Keenable is gate-only: a `tos_matrix.yaml` entry (its terms bar sharing benchmark results) and nothing else, with no `providers.json`, `pricing.yaml` or config entry, no adapter and no live call. Recording a reply (`vendor_confirmation`, and `live_run_allowed` for contextdev) must go in its own FLIP-ONLY PR (R13): `python -m awibench.confirmation_diff [BASE]` (run from `bench/`, default `origin/main`) is structural: it parses `bench/tos_matrix.yaml` and `bench/config.yaml` at the merge-base and at HEAD, compares them field by field, and fails when a confirmation field changes together with anything outside the flip allowlist. The allowlist is: fields inside `providers.<pid>.vendor_confirmation` of ONE flipped provider (any record field: date, sender, quote, evidence_path, recorded_pr); `free_tier_guard.<pid>.live_run_allowed` and `.vendor_confirmation` for that same provider; the vendor-reply evidence file (`[agentwebindex-meta/]cycles/<cycle>/evidence/<file>`, one path segment) and the cycle docs `cycles/<cycle>/summary.md` and `cycles/<cycle>/decisions.md` (only those two names, only directly under `cycles/<cycle>/`; e.g. `cycles/README.md` is rejected). Any other changed key (e.g. `providers.contextdev.benchmarking.quote`, another provider's fields, other config fields), and code, tests, `pricing.yaml`, `providers.json`, README or any other file, are rejected. A price from the vendor reply lands in a separate PR. It runs on every pull request (`.github/workflows/confirmation-diff.yml`, base `origin/<base branch>`) and in `run_tests.sh` (base `AWI_CONFIRMATION_BASE`, default `origin/main`; a missing base fails, and a confirmation_diff failure makes the script exit 1). Bootstrap allowance: a confirmation field that is new at HEAD (absent at the base) and holds the closed default (`null` or `false`) does not count while no entry in `tos_matrix.yaml` or `config.yaml` holds any non-null `vendor_confirmation` or `live_run_allowed: true`, so the PR that introduces a gated provider can carry code; removed fields, changed values, or a HEAD with anything confirmed still fail. AC24h (any PR, not only flips): `confirmation_diff` also fails when an entry that has `vendor_confirmation_required` at the base is lowered, meaning the value goes from `true` to anything else, or the key or the whole entry is deleted or renamed. Deleting or renaming the key fails whatever its base value (`true`, `false` or `null`), per R15. Adding a new gated entry or editing unrelated fields passes. There is no override: lowering the gate needs a separate Fred or CEO ruling. Base-judged CI (R15): `.github/workflows/confirmation-diff-base.yml` runs on `pull_request_target`. It checks out only the base, fetches the PR head as git data, copies the BASE `confirmation_diff.py` and `gates.py` into a temp dir (the flag name comes from the base `gates.py`), and runs them against the PR diff (`python -m awibench.confirmation_diff BASE HEAD` with `AWI_REPO_ROOT`). A PR's own checker, gates.py or workflow never judges that PR, and no PR code is executed. Until #27 merges, the base has no checker, so this job reports BOOTSTRAP and passes. Still open: a branch ruleset must make this check required (Fred). Changed paths are read NUL-separated (`git diff -z`), and path rules use full matches, so a space or trailing newline cannot smuggle a path through.

## Bright Data Web Unlocker (scrape, paid spend guard)
`collectors/benchmark.py` `_brightdata_scrape` POSTs `{"zone", "url", "format": "raw"}` to `https://api.brightdata.com/request` with `Authorization: Bearer $BRIGHTDATA_API_KEY`; the zone comes from env `BRIGHTDATA_ZONE` (`awi_unlocker`). With no key the provider is `skipped_no_key`; with no zone each call is an error billed 0 and no request is made.
Side Hustle CEO, Fred-approved hard cap **$5/month** (config `spend_budget.brightdata`). Before each request the runner reads the month-to-date estimate from `bench/spend/brightdata-YYYY-MM.json` (month of the request's UTC timestamp, so a new month starts a new file) at $1.50 per 1,000 requests ($0.0015 each). If the estimate is already at $4.00, or the next request would take it past $4.00, the provider stops as `stale_budget` (not published, previous row kept, same path as the other stale reasons). The guard allows at most 2,666 requests a month (2,666 x $0.0015 = $3.999), leaving $1.00 of headroom under the cap. Each request's check, bill and spend-file write run under an exclusive `fcntl.flock` (on `bench/spend/.brightdata.lock`, one lock per provider across months, written atomically via rename), so overlapping runs can't push past the $4.00 stop. Rule 6 (CEO ruling 2026-10-19, RULINGS.md): a missing spend file for the current month fails closed (`stale_budget`, no calls) unless it may be seeded at $0. Seeding is allowed only (a) on the first-ever month, when no `brightdata-YYYY-MM.json` exists at all, or (b) when the previous month's file exists, is valid and is not yet closed. Seeding closes it: under the provider lock (`bench/spend/.brightdata.lock`) the runner first writes `rolled_over_to: M` into month M-1's file (atomic temp + rename), then writes the $0 file for M. Refused: M-1 already says `rolled_over_to: M` (this month's file was deleted; every later attempt refuses too), M-1 rolled over to another month, M-1 is corrupt, M-1 is absent while other spend files exist (gap or deletion), or a later month's file exists. A crash after the marker is written but before M's file exists cannot be told apart from "M was deleted mid-month", so it stays refused: M refuses, and M+1 also refuses (previous month absent). Every spend file (current or previous month) must pass the same validation: `provider` = `brightdata`, `month` = its file month, `requests` a non-negative int, `est_usd` a finite non-negative number (no booleans), and an optional `rolled_over_to` that is a later `YYYY-MM` string; anything else fails closed. Manual recovery for a refused month M (crash after the marker, or a deleted file): (1) make sure no benchmark run is in progress; (2) find the true request count N billed for M, from the Bright Data dashboard (zone `awi_unlocker`, month M) or, if the file was never billed (crash right after the marker), N = 0; sum `billed_units` of `bench/runs/YYYY-MM-*/brightdata/*.jsonl` lines for month M as a cross-check and take the larger; (3) write `bench/spend/brightdata-M.json` as `{"provider": "brightdata", "month": "M", "usd_per_1k": 1.5, "requests": N, "est_usd": N x 0.0015 rounded to 6 decimals}`, with no `rolled_over_to`, and leave M-1's `rolled_over_to: M` marker as it is; (4) commit it. The next run in M continues from N. The M+1 gap lockout clears with the same step: once M's file exists without a marker, the first run in M+1 marks M `rolled_over_to: M+1` and seeds M+1 at $0. If M+1 has already started and its own file was billed, recreate M (step 3), then recreate M+1 the same way with its true count, and add `"rolled_over_to": "M+1"` to M's file. Deleting every spend file looks like a first-ever month and cannot be detected locally. Fail-closed cases: if `bench/spend/` is missing or unreadable, or the spend file is empty, corrupt, for another month or has bad fields, Bright Data alone stops as `stale_budget` with the reason logged ("...; failing closed") and the other providers keep running. The month is taken from each request's UTC timestamp, not the run date (Oct 31 21:30 ET bills to 2026-11). Billing follows the status-line rule: a request bills once a status line arrives (including 403, 429, 5xx); 0 for no response or HTTP 401 (ASSUMPTION, accepted by the CEO). Tests are mocked only and refuse to write mock spend into `bench/spend`.

## Adapter contract (collectors/benchmark.py `ADAPTERS`)
`fn(key, item) -> dict`, plus optional `billed_units` (the provider's billing unit; browser = raw minutes), `proxy_gb` and `http_status`.
- search: `{"results": [{"url","title","snippet","published_at"?}, ...]}`
- scrape: `{"text", "html"?}`
- browser: `{"final_url"?, "extracted_value"?, "dom_text"?, "file_bytes"?}`

Marker `selector_text` value format: `"<selector>::<text>"`, with selector = `tag`, `#id`, `.class` or `tag.class`.

**Stale runs still write their run log.** A `stale_<reason>` run's lines go to `bench/runs/YYYY-MM-DD/<provider>/<set>.jsonl` stamped `run_status: stale_<reason>` (spend audit); `tables.collect` never publishes a stamped or incomplete log. Only a provider with no data call and nothing billed writes no lines.
