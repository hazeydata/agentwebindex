## Bright Data Web Unlocker (scrape, paid spend guard)
`collectors/benchmark.py` `_brightdata_scrape` POSTs `{"zone", "url", "format": "raw"}` to `https://api.brightdata.com/request` with `Authorization: Bearer $BRIGHTDATA_API_KEY`; the zone comes from env `BRIGHTDATA_ZONE` (`awi_unlocker`). With no key the provider is `skipped_no_key`; with no zone each call is an error billed 0 and no request is made.
Side Hustle CEO, Fred-approved hard cap **$5/month** (config `spend_budget.brightdata`). Before each request the runner reads the month-to-date estimate from `bench/spend/brightdata-YYYY-MM.json` (month of the request's UTC timestamp, so a new month starts a new file) at $1.50 per 1,000 requests ($0.0015 each). If the estimate is already at $4.00, or the next request would take it past $4.00, the provider stops as `stale_budget` (not published, previous row kept, same path as the other stale reasons). The guard allows at most 2,666 requests a month (2,666 x $0.0015 = $3.999), leaving $1.00 of headroom under the cap. Each request's check, bill and spend-file write run under an exclusive `fcntl.flock` (on `bench/spend/.brightdata.lock`, one lock per provider across months, written atomically via rename), so overlapping runs can't push past the $4.00 stop. Rule 6 (CEO ruling 2026-10-19, RULINGS.md): a missing spend file for the current month fails closed (`stale_budget`, no calls) unless it may be seeded at $0. Seeding is allowed only (a) on the first-ever month, when no `brightdata-YYYY-MM.json` exists at all, or (b) when the previous month's file exists, is valid and is not yet closed. Seeding closes it: under the provider lock (`bench/spend/.brightdata.lock`) the runner first writes `rolled_over_to: M` into month M-1's file (atomic temp + rename), then writes the $0 file for M. Refused: M-1 already says `rolled_over_to: M` (this month's file was deleted; every later attempt refuses too), M-1 rolled over to another month, M-1 is corrupt, M-1 is absent while other spend files exist (gap or deletion), or a later month's file exists. A crash after the marker is written but before M's file exists cannot be told apart from "M was deleted mid-month", so it stays refused: M refuses, and M+1 also refuses (previous month absent). Every spend file (current or previous month) must pass the same validation: `provider` = `brightdata`, `month` = its file month, `requests` a non-negative int, `est_usd` a finite non-negative number (no booleans), and an optional `rolled_over_to` that is a later `YYYY-MM` string; anything else fails closed. Manual recovery for a refused month M (crash after the marker, or a deleted file): (1) make sure no benchmark run is in progress; (2) find the true request count N billed for M, from the Bright Data dashboard (zone `awi_unlocker`, month M) or, if the file was never billed (crash right after the marker), N = 0; sum `billed_units` of `bench/runs/YYYY-MM-*/brightdata/*.jsonl` lines for month M as a cross-check and take the larger; (3) write `bench/spend/brightdata-M.json` as `{"provider": "brightdata", "month": "M", "usd_per_1k": 1.5, "requests": N, "est_usd": N x 0.0015 rounded to 6 decimals}`, with no `rolled_over_to`, and leave M-1's `rolled_over_to: M` marker as it is; (4) commit it. The next run in M continues from N. The M+1 gap lockout clears with the same step: once M's file exists without a marker, the first run in M+1 marks M `rolled_over_to: M+1` and seeds M+1 at $0. If M+1 has already started and its own file was billed, recreate M (step 3), then recreate M+1 the same way with its true count, and add `"rolled_over_to": "M+1"` to M's file. Deleting every spend file looks like a first-ever month and cannot be detected locally. Fail-closed cases: if `bench/spend/` is missing or unreadable, or the spend file is empty, corrupt, for another month or has bad fields, Bright Data alone stops as `stale_budget` with the reason logged ("...; failing closed") and the other providers keep running. The month is taken from each request's UTC timestamp, not the run date (Oct 31 21:30 ET bills to 2026-11). Billing follows the status-line rule: a request bills once a status line arrives (including 403, 429, 5xx); 0 for no response or HTTP 401 (ASSUMPTION, accepted by the CEO). Tests are mocked only and refuse to write mock spend into `bench/spend`.

## Adapter contract (collectors/benchmark.py `ADAPTERS`)
`fn(key, item) -> dict`, plus optional `billed_units` (the provider's billing unit; browser = raw minutes), `proxy_gb` and `http_status`.
- search: `{"results": [{"url","title","snippet","published_at"?}, ...]}`
- scrape: `{"text", "html"?}`
- browser: `{"final_url"?, "extracted_value"?, "dom_text"?, "file_bytes"?}`

Marker `selector_text` value format: `"<selector>::<text>"`, with selector = `tag`, `#id`, `.class` or `tag.class`.

**Stale runs still write their run log.** A `stale_<reason>` run's lines go to `bench/runs/YYYY-MM-DD/<provider>/<set>.jsonl` stamped `run_status: stale_<reason>` (spend audit); `tables.collect` never publishes a stamped or incomplete log. Only a provider with no data call and nothing billed writes no lines.
