## Pre-run check (spec R41: over-cap projection and provider stop)
`runner.check_run`, called by `runner.run` once per run before any provider call (`preflight=True`, the default; only tests of the per-call backstop pass `False`). Any problem refuses the WHOLE run: `runner.RunRefused`, 0 calls, no run log, ledger or counter written. `collectors/benchmark.py` then writes `alerts/over_cap_projected.json` (gitignored), prints `ALERT over_cap_projected.json: <reason>` and the JSON to stderr, and exits 2, so the job fails. Partial runs break set comparability, so there is no partial run.
- **Provider stop (R41.2):** a provider absent from config `known_providers` (the 17 `collectors/providers.json` ids) stops the run, including an unknown `--only-providers` name; so does a provider set to live (`guard.live_allowed` true) without a cap entry (`free_tier_guard.<pid>.quota_credits` and `stop_at_credits` as positive ints; keenable also `rate_limit.max_per_hour`). A missing or malformed `known_providers` fails closed (mock runs may omit it). A known provider that is off for month one keeps `skipped_not_month1` and the run continues.
- **Projection (R41.1):** for every provider that will make calls (the same skip checks as the run, `runner.gate`), per billing pool: planned_calls = the set items the run would call (`--only-sets`, re-probe item filters and ToS-skipped anti-bot items applied; retries not counted); planned units from the per-call worst-case estimate; price = the `cost.cost_columns()` entry-tier list price per unit; projected_usd = planned units x price, in exact `Decimal` (config and ledger floats are read through their shortest repr, so 3.97 + 20 x 0.0015 is exactly 4.00).
  - USD-capped providers (`meter_budget` Apify, `spend_budget` Bright Data): remaining_usd = `stop_usd` ($4.00; Apify: Fred's approved $4 monthly cap, Oct 26 2026 8:25 AM ET, config `meter_budget.apify.approved`; Bright Data: the guard's $4.00 stop under the Fred-approved $5 hard cap `cap_usd`, config `spend_budget.brightdata.note`; spec R42.3: caps use `stop_usd`) minus month-to-date spend (Apify: ledger pool x `ledger_unit_usd`; Bright Data: the `bench/spend/brightdata-YYYY-MM.json` `est_usd`). Refused when projected_usd > remaining_usd; exactly at the cap runs.
  - Every provider also against its free quota (D4 and spec R42.3: planned calls, as their estimated units, against the remaining free quota; the $0 USD cap means no paid call beyond it): remaining = quota minus the month's ledger, and for a `free_tier_guard` provider also `stop_at_credits` minus its window counter (keenable's UTC-hour counter, contextdev's anchor window). Refused when planned units > remaining; remaining_usd = the smaller of the USD remaining and the remaining units at list price.
  - Keenable: planned calls plus this UTC hour's counter must be <= `rate_limit.max_per_hour` (899): 899 runs, 900 refuses.
  - A missing price (pricing `NOT CAPTURED`), a missing cap, an unknown per-call cost, or an unreadable counter or spend file refuses the run.

Deleting every spend file looks like a first-ever month and cannot be detected locally. ## Stop rules (config `stop_on_http`)
A provider stops at its first HTTP 401/403 (`stale_auth_error`) and at its first HTTP 402 or Apify payment/usage-limit error code in the body, even with HTTP 200: `payment-required`, `usage-limit-exceeded`, `platform-feature-disabled`, `not-enough-usage-to-run-paid-actor` (`stopped_paid_usage`, from `stop_on_http["402"]`). Each of these stops every category of that provider for the rest of the run (for Apify, search and browser alike), and the categories that did not run show `provider stopped earlier this run`. The other providers keep running. These HTTP stops (`stop_on_http`) apply to all providers, Apify, Bright Data and the rest alike. A provider also stops after `stop_on_http["429_consecutive"]` (3) HTTP 429 answers in a row (`stopped_rate_limited`). After each 429 the runner waits the `Retry-After` seconds the provider sent, capped at `retry_after_max_s` (60 s), and waits `retry_after_default_s` (0 s) when the header is absent. A success resets the streak; a client timeout neither resets nor advances it. Calls are sequential, so a run's concurrency is 1. CEO rule 3 (more than 20% of calls answered 429) still applies to runs that finish. `stopped_*` and `stale_*` runs are never published.

Spend guard (Apify, `meter_budget.apify`): before each call the guard refuses the call (`stopped_budget`, as for an unreadable meter) if max(live meter, ledger) is already at the $4.00 stop or if it plus the next call's estimate would pass $4.00. The estimates are 4.08 cents for a RAG search (`pricing.yaml` `credits_per_call.search`, measured: the live meter moved $0.8563 over the 21 RAG calls of 2026-10-26) and 0.155 cents for a Web Fetch call. A per-call cost the pricing does not define fails closed (`stopped_budget`, "unknown per-call cost"), never assumed to be 1. Worked example at the meter reading of $3.9026: two more RAG searches are allowed ($3.9434, then $3.9842), the third ($4.0250) is refused, and Web Fetch calls (0.155 cents) are still allowed until the next one would pass $4.00. When a call bills more than its estimate, or the month-to-date total passes the stop, the run records `cap_overrun` on the log line, in the run summary and in `bench/spend/apify-cap-overrun-YYYY-MM.json`, with `alert: chief` (the runner does not message anyone; the operator alerts chief). The ledger, meter log and run summary are written atomically (temp file + `os.replace`). Every log line carries `cost_estimate_units`, `cumulative_spend` (month-to-date units after the call) and, for Apify, `cumulative_usd`. Every run summary carries `run_spend_units`, `cumulative_spend_units` and, for Apify, `run_spend_usd` / `cumulative_spend_usd`.

Timeouts (Apify): a client timeout on an Apify call is a fail (`status: fail`, `pass: false`, `timeout: true`, reason contains `TimeoutError`). It is billed at the call's estimate and logged; even a run where every call timed out writes its lines. Other providers keep the CEO status-line rule (no status line = `unbilled_no_response`).
